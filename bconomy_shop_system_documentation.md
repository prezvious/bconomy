# Bconomy Shop System — Complete Technical & Balance Documentation

## 1. Purpose

This document defines the complete **Bconomy system shop** for buying and selling in-game items, including:

- 10-minute per-player restocks
- item appearance rolls
- stock generation
- sell-price generation
- buy-price generation
- item eligibility rules
- full item balance tables
- T1–T4 loot booster balance
- booster stacking and activation behavior
- player-state additions
- backend engine responsibilities
- REST API contracts
- frontend behavior
- validation and anti-exploit rules
- probability formulas
- testing requirements
- known integration prerequisites

The shop is intended to be a **supplemental progression system and cash sink**, not a replacement for Mining, Exploring, Hunting, Fishing, or Farming.

---

# 2. Core Design Goals

The system should satisfy the following principles:

1. **Legacy items use value-band buy markups; farm upgrade materials use explicit independent buy and sell ranges whose intentional overlap supports the market-luck mechanic.**
2. **The shop restocks every 10 minutes.**
3. **Stock does not accumulate between restocks.**
4. **Every restock fully replaces the previous shop inventory.**
5. **Appearance chance is the primary scarcity gate for high-tier items.**
6. **High-tier items may appear in meaningful quantities when their rare shop roll succeeds.**
7. **All normal in-game items are eligible for the Buy shop unless explicitly excluded.**
8. **All normal non-booster items are sellable unless explicitly excluded.**
9. **Boosters cannot be sold.**
10. **T5 and T6 boosters never appear in the system shop.**
11. **T1–T4 boosters are buy-only premium items.**
12. **Different booster tiers stack multiplicatively.**
13. **Multiple copies of the same booster tier extend duration instead of multiplying that tier again.**
14. **All shop randomness is generated by the backend.**
15. **The frontend never decides prices, appearance, or stock.**

---

# 3. Restock Model

## 3.1 Restock Interval

The shop restocks every:

\[
R = 600\text{ seconds} = 10\text{ minutes}
\]

Therefore, the maximum number of normal restock opportunities in one 24-hour period is:

\[
N_{\text{day}}
=
\frac{24\times 60}{10}
=
144
\]

Each player has their own shop state and restock timestamp.

---

## 3.2 Full Replacement

At each restock:

1. The old Buy stock is discarded.
2. New appearance rolls are performed.
3. New stock quantities are rolled for successful appearances.
4. New sell prices are rolled.
5. New buy prices are rolled.
6. The next restock timestamp is set to 10 minutes after the current restock.

Unsold stock **does not carry over**.

---

# 4. Appearance-Chance Model

For each purchasable item \(i\), define:

- \(p_i\): appearance chance expressed as a decimal
- \(A_i\): whether the item appears during the current restock

Then:

\[
A_i \sim \operatorname{Bernoulli}(p_i)
\]

Equivalently:

\[
P(A_i=1)=p_i
\]

and:

\[
P(A_i=0)=1-p_i
\]

For example, an item with a `0.50%` appearance chance has:

\[
p_i = 0.005
\]

---

## 4.1 Probability of Seeing an Item at Least Once

Across \(n\) independent restocks:

\[
P(\text{at least one appearance})
=
1-(1-p_i)^n
\]

For one full day of 144 restocks:

\[
P_{\text{day}}
=
1-(1-p_i)^{144}
\]

---

## 4.2 Expected Number of Appearances

Across \(n\) restocks:

\[
E[X_i]=n p_i
\]

For one day:

\[
E[X_{i,\text{day}}]
=
144p_i
\]

---

## 4.3 Expected Time Between Appearances

Because one roll occurs every 10 minutes, the expected waiting time between successful appearances is:

\[
E[T_i]
=
\frac{10}{p_i}
\text{ minutes}
\]

where \(p_i\) is expressed as a decimal.

Example for a `0.10%` chance:

\[
p_i=0.001
\]

\[
E[T_i]
=
\frac{10}{0.001}
=
10{,}000\text{ minutes}
\approx
6.94\text{ days}
\]

---

# 5. Stock Generation

If an item appears, its stock quantity is rolled uniformly over its configured inclusive integer range:

\[
Q_i \in [q_{\min,i},q_{\max,i}]
\]

Let:

\[
U\sim\operatorname{Uniform}[0,1)
\]

Then:

\[
Q_i
=
q_{\min,i}
+
\left\lfloor
U\left(q_{\max,i}-q_{\min,i}+1\right)
\right\rfloor
\]

This produces an integer uniformly distributed across the configured stock range.

If the appearance roll fails:

\[
Q_i=0
\]

The UI should display:

`No stock available`

and disable purchase controls for that item.

---

# 6. Sell-Price Generation

Each sellable item has a configured inclusive sell-price range:

\[
[s_{\min,i},s_{\max,i}]
\]

A single sell price is rolled once per restock:

\[
P_{\text{sell},i}
=
s_{\min,i}
+
\left\lfloor
U\left(s_{\max,i}-s_{\min,i}+1\right)
\right\rfloor
\]

where:

\[
U\sim\operatorname{Uniform}[0,1)
\]

The rolled sell price remains fixed for that item until the next restock.

This prevents transaction-by-transaction reroll abuse.

---

# 7. Buy-Price Generation

Legacy item buying is significantly more expensive than selling. Farm upgrade materials are the deliberate exception described in §7.2.

The Buy shop does **not** reuse the current sell price. Instead, it calculates the purchase price from the item's configured maximum sell price.

Let:

\[
S_i=s_{\max,i}
\]

Then a markup multiplier \(M_i\) is rolled based on the item's value band.

## 7.1 Markup Table

| Maximum Sell Price \(S_i\) | Buy Multiplier Range |
|---:|---:|
| \(S_i \le \$10{,}000\) | \(3\times\) to \(5\times\) |
| \(\$10{,}000 < S_i \le \$200{,}000\) | \(4\times\) to \(6\times\) |
| \(\$200{,}000 < S_i \le \$1{,}000{,}000\) | \(5\times\) to \(7\times\) |
| \(\$1{,}000{,}000 < S_i \le \$10{,}000{,}000\) | \(6\times\) to \(8\times\) |
| \(\$10{,}000{,}000 < S_i \le \$100{,}000{,}000\) | \(7\times\) to \(10\times\) |
| \(\$100{,}000{,}000 < S_i \le \$1{,}000{,}000{,}000\) | \(8\times\) to \(12\times\) |
| \(S_i > \$1{,}000{,}000{,}000\) | \(10\times\) to \(15\times\) |

Let:

\[
M_i\sim\operatorname{Uniform}[m_{\min,i},m_{\max,i}]
\]

Then:

\[
P_{\text{buy},i}
=
\operatorname{round}(S_iM_i)
\]

The buy price is rolled once during restock and remains fixed until the next restock.

Because the smallest possible multiplier is \(3\):

\[
P_{\text{buy},i}
\ge
3S_i
\]

and because:

\[
P_{\text{sell},i}\le S_i
\]

it follows that:

\[
P_{\text{buy},i}
>
P_{\text{sell},i}
\]

for every normal item.

This makes direct buy-then-sell arbitrage impossible.

## 7.2 Farm Upgrade Material Exception

Farm upgrade materials configure an explicit `buyRange` in addition to `sellRange`. On every 10-minute refresh, the backend independently rolls one sell price and—if the item appears—one buy price inside those respective inclusive ranges. The ranges intentionally overlap. A lucky refresh can therefore offer a favorable relationship, and that variance is part of the market mechanic rather than a pricing error. All legacy entries without `buyRange` retain the markup-band formula in §7.1.

# 8. Transaction Rules

## 8.1 Buying

A purchase is valid only when all of the following are true:

1. The item is purchasable.
2. The item appeared in the current restock.
3. Requested quantity is a positive integer.
4. Requested quantity does not exceed current stock.
5. The player has sufficient cash.
6. The request uses the current server-side shop state.

For quantity \(q\):

\[
C=qP_{\text{buy},i}
\]

The purchase succeeds only if:

\[
\text{cash}\ge C
\]

On success:

\[
\text{cash}_{\text{new}}
=
\text{cash}_{\text{old}}-C
\]

\[
\text{inventory}_{i,\text{new}}
=
\text{inventory}_{i,\text{old}}+q
\]

\[
\text{stock}_{i,\text{new}}
=
\text{stock}_{i,\text{old}}-q
\]

---

## 8.2 Selling

A sale is valid only when:

1. The item is sellable.
2. The requested quantity is a positive integer.
3. The player owns at least the requested quantity.
4. The item is not a booster.

For quantity \(q\):

\[
R=qP_{\text{sell},i}
\]

Then:

\[
\text{cash}_{\text{new}}
=
\text{cash}_{\text{old}}+R
\]

\[
\text{inventory}_{i,\text{new}}
=
\text{inventory}_{i,\text{old}}-q
\]

Boosters must always be rejected by the Sell endpoint.

# 11. Booster Stacking

Different active tiers stack multiplicatively.

If \(k\) distinct booster tiers are active:

\[
B=2^k
\]

Examples:

### Two active tiers

\[
B=2\times2=4
\]

### Four active tiers

\[
B=2^4=16
\]

### All six tiers active

\[
B=2^6=64
\]

Therefore:

\[
2\times2\times2\times2\times2\times2=64
\]

---

## 11.1 Same-Tier Activation

Multiple copies of the **same tier do not multiply** the loot bonus.

Instead, activating another copy extends the expiration time.

Let:

- \(t_{\text{now}}\): current timestamp
- \(t_{\text{expire}}\): current tier expiration timestamp
- \(D\): booster duration

Then:

\[
t_{\text{expire,new}}
=
\max(t_{\text{now}},t_{\text{expire,old}})+D
\]

This preserves one \(2\times\) multiplier for that tier while extending its active duration.

# 12. Booster Integration With Action Loot

For a resource action, define:

- \(R\): base roll pool
- \(c_i\): item drop chance as a decimal
- \(T\): tool multiplier
- \(S_i\): Serendipity rare-drop multiplier
- \(B\): total booster multiplier

Then the expected pre-variance yield is:

\[
E_i
=
R
\times
c_i
\times
T
\times
S_i
\times
B
\]

If \(E_i\ge1\), the final yield follows the normal action variance system.

Using variance factor:

\[
V\sim\operatorname{Uniform}[0.96,1.04]
\]

the yield is:

\[
Y_i
=
\max
\left(
1,
\operatorname{round}(E_iV)
\right)
\]

If:

\[
E_i<1
\]

then the result is probabilistic:

\[
P(\text{drop})=E_i
\]

and a successful roll yields exactly one unit.

All other system multipliers continue to stack multiplicatively unless explicitly defined otherwise.

# 19. Persistence

Shop state should persist in the player's saved state so:

- page refreshes do not reroll stock
- reconnecting does not reroll stock
- repeated API calls do not reroll prices
- restocking happens only when the actual restock boundary has passed

A shop refresh must therefore be **time-gated**, not request-gated.

# 24. Balance Interpretation

The intended economy is:

## Action loot

- **Fishing:** highest sell values in the millions
- **Hunting:** highest sell values in the hundreds of thousands
- **Mining:** highest sell values in the tens of millions
- **Exploring:** highest sell values in the tens of millions, always below \$50 million

## Non-action materials

Approximate minimum progression:

- Common: \$200 to \$10,000
- Uncommon: \$20,000 to \$200,000
- Rare / Epic / Legendary: hundreds of thousands to several million
- Mythical: tens of millions
- Highest-tier: billions to tens of billions

The shop should therefore create a strong progression sensation:

\[
\text{thousands}
\rightarrow
\text{hundreds of thousands}
\rightarrow
\text{millions}
\rightarrow
\text{tens of millions}
\rightarrow
\text{billions}
\]

---

# 25. Important Balance Principle

High stock does **not** necessarily make a rare item common.

Scarcity is determined jointly by:

\[
\text{availability}
=
\text{appearance probability}
\times
\text{stock quantity}
\times
\text{player affordability}
\]

For ultra-rare items, the shop intentionally uses:

- very low appearance probability
- potentially meaningful stock when the roll succeeds
- extremely high purchase prices

This creates rare, memorable shop events without making the item continuously available.

# 26. Final V1 Rules Summary

1. Shop restock interval: **10 minutes**
2. Restocks per day: **144**
3. Restock type: **full replacement**
4. Sell price: one uniform roll per item per restock
5. Legacy buy price: based on `maxSellPrice` plus a large value-band markup
6. Farm upgrade material buy and sell prices: independent configured rolls with intentional overlap
7. Shop stock is rolled only if the appearance check succeeds
8. `No stock available` is shown for zero stock
9. All normal items are purchasable unless explicitly excluded
10. All normal non-booster items are sellable
11. Boosters are never sellable
12. T1–T4 boosters are purchasable
13. T5/T6 boosters are never sold by the shop
14. Different booster tiers stack multiplicatively
15. Same-tier boosters extend duration instead of multiplying again
16. Shop state is server-authoritative
17. Shop state persists through refresh/reconnect
18. Client-provided prices and stock are never trusted
19. Mining stock always stays above 400 and below 20,000
20. Highest-tier Mining stock stays below 5,000
21. Manuscript and Encrypted Drive shop stock stays above 20 and below 200
22. Legacy buy markup functions as the primary system-shop cash sink
23. Backchannel does not modify V1 system-shop prices
24. Canonical item identifiers must be normalized before implementation
